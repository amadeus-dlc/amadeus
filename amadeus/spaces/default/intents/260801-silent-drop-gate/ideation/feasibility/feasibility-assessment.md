# Feasibility Assessment — no-silent-drop

## 評価の前提

本評価は、`ideation/intent-capture/intent-statement.md` で定義された「無音化を構造的に書けなくする静的ゲート」と、関連するランタイム fail-closed 化を対象とする。スコープは `self-feature`、深度は Standard、テスト戦略は Comprehensive である。

調査対象には Issue #1979、#1878、#1874、#1963、既存の `callsite-guard`、complexity gate、GitHub Actions の lint ジョブを含めた。Issue #1963 は Intent 開始後に PR #1970 で修正済みとなったため、重複実装ではなく最新 `main` 統合後の回帰検証へ変更する。

## 結論

**条件付きで実現可能**と判断する。既存リポジトリには shrink-only ratchet、コミット済みベースライン、CI fail-closed、fixture による赤・緑実証の先行パターンがあり、導入方式を新規発明する必要はない。

実装開始前の必須条件は次の3点である。

1. PR #1970 を含む最新 `main` を統合し、#1963 を回帰検証対象へ切り替える。
2. ast-grep のバージョンを再現可能な形で固定し、Bun の frozen install と整合させる。
3. 初期検出母集団を分類し、偽陽性率5%以下を満たせない場合はベースライン追加ではなくルール改善を優先する。

## 技術的実現可能性

### 静的ゲート

- 走査対象は手書き正本の `packages/framework/core/`、`packages/framework/harness/`、`scripts/` とする。
- `dist/`、ルートへ生成される各ハーネス投影、テスト fixture は除外する。生成物は正本から再生成され、fixture は意図的な違反を含みうるためである。
- 3形態（握り潰す catch、成否を返す呼び出しの戻り値破棄、偽成功）を positive / negative fixture で固定する。
- ベースラインと免除は増加を通常更新として受け入れず、減少方向だけを許可する。
- ast-grep・ルール・ベースライン・走査のいずれかが成立しない場合は成功へ丸めず、型付き診断を伴って失敗させる。

### ランタイム fail-closed 化

- #1878 は、永続化失敗を記録済みとして返さず、呼び出し元まで失敗を伝播できる契約が必要である。
- #1874 は、各 callsite で対象行の存在保証を棚卸しし、保証できない経路だけを loud failure または再同期誘導へ変更する。全 callsite を機械的に同一挙動へ変えるのではなく、前提の実測を伴う。
- #1963 は PR #1970 の修正を再実装せず、統合後に `section-unrecognized` と state バイト不変の回帰契約を確認する。

## AWS Platform 観点

新規 AWS サービス、AWS アカウント、ネットワーク、データストア、デプロイ環境は不要である。実行場所は既存の GitHub Actions lint ジョブと開発者のローカル CLI であり、AWS のサービス制約・コスト・データレジデンシーは本 Intent では N/A とする。

クラウド基盤上の制約ではなく、CI の再現性、依存バージョン固定、実行時間15秒以内がプラットフォーム上の主要制約である。

## Compliance 観点

新規の個人情報、決済情報、医療情報、越境データ処理は発生しないため、PCI DSS、HIPAA、GDPR 等の追加適用は確認されない。

一方で、Amadeus の state と audit の整合性はガバナンス上の証拠能力に直結する。したがって次を必須とする。

- ゲート失敗を成功に丸めない。
- ベースライン・免除には理由と差分証跡を残す。
- ランタイム修正では、失敗時に state を部分更新しないことを検証する。
- CI の検出結果とベースライン減少を再現可能な成果物として残す。

## 合否基準

| ID | 基準 | 合格条件 |
|---|---|---|
| F-01 | 検出範囲 | 3形態の positive / negative fixture を100%分類 |
| F-02 | 実データ精度 | 初期検出母集団の偽陽性率が5%以下 |
| F-03 | 実行時間 | CI の単独ステップが15秒以内 |
| F-04 | 内部障害 | ツール・ルール・ベースライン・走査異常がすべて非0終了 |
| F-05 | 新規違反 | ベースライン外の違反と新規免除が CI fail |
| F-06 | 残債減少 | #1878 / #1874 の修正でベースライン件数が減少 |
| F-07 | 外部修正統合 | PR #1970 統合後に #1963 の回帰契約が green |
| F-08 | 配布整合 | 正本変更から全配布投影を再生成し、drift guard が green |

## 推奨判断

上記条件を Scope Definition と後続要件へ引き渡し、**Go** とする。現時点の blocking constraint はない。ただし、PR #1970 未統合のまま #1963 を再実装すること、または偽陽性を無理由でベースラインへ押し込むことは No-Go とする。
