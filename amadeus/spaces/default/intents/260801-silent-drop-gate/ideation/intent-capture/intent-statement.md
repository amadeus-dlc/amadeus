# Intent Statement — 260801-silent-drop-gate

## Problem Statement

Amadeus フレームワークのバグは「無音化」パターン（失敗が成功に見える欠陥）が最大の根本原因族である。全バグ Issue 259件の分類で、無音化は53件（分類済み181件中29%）を占め、直近の S1-FATAL 3件（#1906/#1959/#1960）がすべてこの族だった。形態は3つに集約される:

1. 空の catch / log のみで握り潰す catch（例: #1961）
2. emit 系・Result 系の戻り値を検査せず破棄（例: #1959、#1878）
3. emit だけして書かない / 実態なしに成功を返す偽成功（例: #1960、#1963、#1027）

さらに、同じ根のバグを人力で棚卸しする対症療法が反復している（#1849→#1874/#1878、#1860→#1961/#1963）。個別修正の速度では追いつかず、モグラ叩き状態が続いている。防止の仕組み（無音化を構造的に書けなくするゲート）が存在しないことが構造的問題である。

## Target Customer

2層の受益者を想定する:

- **フレームワーク開発者**（本リポジトリの開発者）: no-silent-drop 静的ゲートの直接利用者。新規の無音化違反が PR 時点で CI fail になり、レビュー・マージ後の後追い修正が不要になる
- **Amadeus ユーザー**（ワークスペースに導入する各チーム）: コア配布物に同梱されるランタイム fail-closed 化の恩恵を受ける。無音化バグはユーザーの record/audit を直接破壊する（#1959/#1960 型）ため、ユーザー恩恵は副次ではなく本質である

## Success Metrics

機械的に検証可能な2指標を成功の定義とする:

1. **検出の実証**: 新規の無音化違反（3形態のいずれか）を含む変更が CI で fail することを、本 intent 内で実測して示す
2. **残債の単調減**: ゲートのベースライン登録数が、混ぜる関連バグ3件（#1878/#1963/#1874）の修正によって減少することを実測して示す（モグラ叩きからの脱却を数で示す）

## Initiative Trigger

2つの実測事実の併記をもってトリガーとする:

- **モグラ叩きの実測**: 無音化53件・同根の人力棚卸しの反復（#1849→#1874/#1878、#1860→#1961/#1963）により、個別修正では追いつかないことが実証されている
- **致命傷の集中**: 直近の S1-FATAL 3件（#1906/#1959/#1960）がすべて無音化族であり、データ・監査整合性の破壊が繰り返し発生している

## Initial Scope Signal

- **スコープ**: self-feature（Amadeus 自己開発・新規機能）
- **本 intent に含めるもの**: no-silent-drop 静的ゲートの新設（Issue #1979）、関連バグ3件（#1878/#1963/#1874）の修正、コア配布物へのランタイム fail-closed 化
- **本 intent に含めないもの**: #1906（S1、並行ロック競合 — 調査が重く別 intent）、既存違反の一括修正（ベースライン登録で許容し個別 Issue で対処）、Biome ルール強化全般
