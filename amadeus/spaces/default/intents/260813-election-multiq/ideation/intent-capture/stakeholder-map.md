# Stakeholder Map — Election CLI 多問対応

## Key Stakeholders and Interests

| ステークホルダー | 関心 | 期待する成果 |
|---|---|---|
| Amadeus conductor | Election の安全な実行と再実行 | 問いごとの裁定を取得し、保留分だけを再実行できる |
| Amadeus メンテナー | データ契約の一貫性、保守性、回帰防止 | 多問対応が単問フローを壊さず、モデルと CLI の責務が明確である |
| 裁定の監査者 | 結果と根拠の追跡可能性 | 各問いの choice・GoA・留保を保存済み tally から検証できる |
| 既存単問 Election の利用者 | 互換性と安定性 | 既存データと既存コマンドが後方読み取り可能である |
| テスト・品質担当 | 受入条件の再現性 | 部分成立、部分保留、部分再実行、互換読み取りを自動検証できる |

## Decision-makers and Influencers

- 最終意思決定者: ユーザー。利用者に見える仕様変更、スコープ外変更、不可逆操作を裁定する。
- Intent 内の通常判断: full autonomy のグラント下で Amadeus の裁定ラダーが処理する。
- 技術的決定者: conductor と Amadeus メンテナー。後続の設計・実装ステージでデータモデルと移行契約を具体化する。
- 影響者: 監査者、既存単問 Election の利用者、品質担当。追跡可能性、互換性、検証可能性の観点を提供する。
- 正本となる要求: [Issue #2813](https://github.com/amadeus-dlc/amadeus/issues/2813) の受入条件と、この Intent で承認された成果物。

## Communication Requirements

- 各ステージの成果物では、問い単位の識別、部分成立、部分再実行、単問互換性の対応関係を明示する。
- 互換性を変更する判断は、旧形式の読み取り例と新形式の書き込み例を併記してレビュー可能にする。
- 品質報告では、既存単問回帰と新規多問シナリオを分けて結果を示す。
- full autonomy の自動裁定は監査ログへ残し、未レビューの裁定を追跡できるようにする。
- 新規権限、不可逆操作、スコープ外変更、規範または品質の免除が必要になった場合は、自動化せずユーザーへ明示する。
