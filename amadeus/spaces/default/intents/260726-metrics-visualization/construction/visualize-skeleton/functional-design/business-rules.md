# Business Rules — U1 visualize-skeleton

上流入力(consumes 全数): unit-of-work.md, unit-of-work-story-map.md, requirements.md, components.md, component-methods.md, services.md

## ルール一覧

1. **fail-closed / zero-write**(requirements.md FR-2): 入力集合に1件でも不正スナップショットがあれば index.html を書かない。部分描画・スキップ描画をしない(retention の zero-deletions と同型)
2. **exit code 契約**(FR-1 / component-methods.md): 成功 0 / 実行時失敗(空・不在・per-file 読込失敗(permission / dangling symlink 等)・parse 失敗)1 / usage 違反 2。失敗はすべて非空 stderr を伴う
3. **パーサ単一正本**(FR-2): 妥当性判定は parseSnapshot のみ。visualize 側で JSON.parse を直接呼ばない
4. **数値は numericValue 経由のみ**(FR-3): チャート座標・集計に raw values を使わない。非有限値・非 number は欠測(null)
5. **エスケープ必須**(FR-3): HTML へ埋め込む動的文字列(commit・captured_at・コレクタ名・キー名・tool/tool_version)は全数 escapeHtml 経由。unionValueKeys 由来のキー名も対象(スナップショットデータは信頼境界内だが、書式健全性のため全数)
6. **データ駆動表示**(FR-3): コレクタ名・キー名のハードコード禁止(discoverCollectors / unionValueKeys のみ)。未知コレクタも表示される(強調は U2 で追加されるまで全コレクタ無強調)
7. **SHA 遡及**(FR-4 S3 / AC-3): 各データ点の `<title>` に captured_at + commit 先頭12桁。加えて各コレクタ節の値表に commit 12桁列を置く(hover 不能環境のフォールバック)
8. **生成物の正本分離**(constraint C2): index.html 先頭に「generated by scripts/metrics-visualize.ts — do not edit」コメント(英語 — コード面)
9. **self-contained**(FR-3): 出力 HTML に `http://` / `https://` の参照を含まない(unit テストで grep assert — story-map「見る」ジャーニーが file:// で完結する条件)
10. **AC-1c 不変**(AC-7): metrics-timeseries.ts へ fs write API の import を追加しない(T-1 の契約 grep で機械検査)
11. **renderHtml の決定性**(AC-5 の前提): 同一入力(スナップショット集合)→ 同一バイト列。wall-clock・乱数・環境値を出力に埋め込まない。メタ行はデータ由来の決定値(件数・期間・最新 commit)のみ — これにより U2 の `--check` バイト比較が成立する(reviewer it.1 Critical-1 の是正)

## U1 で適用しないルール(U2 予約 — 無申告スコープ縮小ではなく計画済み分割)

- 劣化強調(AC-2)・サイズ上限(FR-6)・`--check`(AC-5)・CI 同乗(AC-6)・docs(AC-8)— unit-of-work.md U2 に割当済み
