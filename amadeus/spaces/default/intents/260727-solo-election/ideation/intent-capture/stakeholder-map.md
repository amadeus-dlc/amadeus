## ステークホルダー一覧

| ステークホルダー | 役割 | 関心事 | 影響度 |
|---|---|---|---|
| ソロモードのユーザー(裁定者) | 発行者・最終裁定者 | 裁定負荷の軽減。割れたケース(1-1/ブロック/棄権)だけが自分に上がること。裁定の事後追跡可能性 | 高 — 第一受益者 |
| conductor(main agent) | 選挙管理委員 | 選挙 open・blind verbatim 配布・開票の定型手順が typed directive で迷いなく実行できること。自身は投票しない境界の明確さ | 高 |
| subagent 投票者(2体) | 投票者 | blind ballot だけを受け取り、fresh context で独立に実測・投票できること。CLI 投票の完遂(同期完遂の定型文言) | 高 |
| チームモードの利用チーム | 既存機能の利用者 | member 投票経路・GoA 規則・agmsg 輸送の無退行 | 中 — 変更なしが要件 |
| フレームワーク保守者 | CLI/SKILL/ノルムの保守 | solo/team の輸送分岐が election CLI の単一状態機械に収まり、二重実装にならないこと。テスト(両分岐の落ちる実証)の保守性 | 中 |
| 他ハーネス利用者(codex/cursor/opencode/kimi/kiro) | 配布物の利用者 | SKILL.md ソロ分岐と CLI 変更が7ハーネス dist・self-install に同期されること。spawn 不能ハーネスでの loud な降格 | 中 |

## 権限と裁定の境界

- **ユーザー専権(選挙対象外)**: 仕様変更、エスカレーション正準リスト事項(マージ・不可逆操作・人間関与が本質の事項)、1-1 スプリット/ブロック/棄権時の最終裁定。
- **2体選挙で裁定可能**: 設計逸脱・ブロッカー・§13 学習選定(自動発動)、およびユーザーが明示的に選挙へかけた事項。
- **main agent の境界**: 選挙管理(open・配布・開票・record 固定)のみ。投票・裁定への実質関与は禁止。
