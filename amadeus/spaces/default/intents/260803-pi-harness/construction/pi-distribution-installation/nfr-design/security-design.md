# Pi Distribution / Installation — Security Design

## 適用範囲

本設計はPi setup fresh/update/uninstallとPi Package local/git routeを、同一authored resourceからproject-local resourceへ投影する配布境界を保護する。engine-resolved `consumes` は空で、条件付きの `security-requirements` / `tech-stack-decisions` も期待どおり不在である。新しい要件を作らず、既決のPi harness、setup transaction、root package view、hash parity、generated drift guardをsecurity controlへ落とす。

transaction journal/rollback、runtime lifecycle、child execution、doctor、formal live evidenceは各所有Unitの責務である。本Unitはそれらのartifactを配布candidateへ束ねるが、意味論や成功receiptを再定義しない。

## Trust and provenance model

| Zone | Authority | Untrusted observation |
|---|---|---|
| Authored Pi sources | reviewed harness/core source + source revision | generated tree、target installation |
| Expected catalog | build時にverifierへ束縛されたmanifest projection | observed manifest/resource count |
| Setup candidate | expected catalog検証済みproject payload | stale/tampered `dist/pi` |
| Pi Package source view | expected catalogと同revisionのprivate root metadata | moving Git ref、local dirty tree |
| Target project | user-controlled filesystem | existing/modified managed files |
| Pi runtime | native project trust owner | untrusted/unapproved project-local code |
| Git/package manager | source acquisition/credential owner | URL、dependency graph、lifecycle scripts |

Pi project trustはload authorizationでありsandboxではない。installer/projectorはtrust storeを編集せず、`--approve`を自動化せず、untrusted projectでresourceをloadしてworkflowを起動しない。インストール完了とruntime trust/activation成功を同じresultにしない。

## Single source and dual-view projection

authored Pi harness manifestとshared core inventoryからcanonical `PiDistributionExpectedCatalog`を生成する。catalogはschema、framework version、source revision、resource ID/kind、authored source、setup destination、package resource path、content digest、mode、minimum Pi versionを持つ。

projectorは一つのimmutable candidate graphから次の2 viewを生成する。

1. setup view: `dist/pi/.pi/...` など対象project rootへ導入するpayload。root `package.json`を含めない。
2. Pi Package view: source repository rootのprivate package metadataにあるclosed `pi` resource declaration。setup viewと同じgenerated bytesをrepository-relative pathで参照する。

expected catalogはrunning verifierに束縛し、observed `dist/pi`、root `package.json`、target install manifestを期待値へ使わない。resourceとobserved manifest entryを同時削除、rename、kind変更してもexpected setとの差分になる。

projection pathはnormalized repository-relative path、no NUL/absolute/`..`、case-fold/Unicode collisionなし、symlinkなし、regular fileのみとする。sourceをread前後にidentity/digest再検証し、source swapではcandidate publish 0とする。

## Root package metadata controls

Pi Package metadata projectionは既存root `package.json`全体を書き直さず、typed JSON parserで許可された`pi` fieldだけをcanonical更新する。format/comment保持が不可能なJSONであるため、unknown top-level fieldを削除・並べ替えないことをbyte-diff fixtureで検証する。projection対象外fieldにdiffが出た場合は失敗する。

正式candidateのroot package security profileは次を必須とする。

- `private: true` を保持し、publish routeを追加しない。
- `preinstall` / `install` / `postinstall` / `prepare` 等のpackage-install lifecycle scriptをPi対応変更から追加しない。既存fieldがある場合は明示riskとしてcatalogへsafe booleanで示し、formal local/git install profileはfail-closedにする。
- `pi` resource pathはexpected catalog内のregular fileだけを参照し、任意entrypoint/path globを許可しない。
- package metadataへAPI key、token、home path、machine-local provider/model設定を埋め込まない。
- dependency/lockfile snapshotをsource revisionへ束縛し、projection後にlockfileをsilent rewriteしない。

Pi installがrepository root dependencyをinstallし得ることは隠さない。distributionはdependencyをdownload/executeせず、root packageの既存dependency graphを「安全」と自己認証しない。正式手順ではreview済みimmutable source revisionとlockfile diffを提示し、Pi/package managerが実行するcodeはuser trust boundary内であると明示する。

## Local and Git source identity

### Local route

local sourceはcanonical realpath、repository identity、current revision、dirty state、expected catalog digestを観測する。formal parity sourceとして受理するのは同一repository/revisionのclean generated candidateである。dirty sourceはdevelopment用typed warningまたはformal-blockedとし、clean sourceと同じprovenanceを名乗らない。

`pi install -l` のlink/copy semanticsはPiへ委譲するが、package viewからtarget外任意pathへescapeするresource declarationを作らない。local absolute pathはmachine-local observationであり、manifest/audit/formal evidenceへ保存しない。

### Git route

正式git source identityはcredential-free canonical repository URLとimmutable commit SHAである。moving branch、unresolved tag、default branch、abbreviated SHAをformal identityにしない。annotated tagを案内する場合も解決済みcommitをevidenceへ保持する。

Git credential、SSH agent、token、proxy credentialはGit/Piの通常環境へ委譲し、distribution codeはparse、copy、hash、persist、logしない。URLからuserinfo/query secretを除去できない場合はdiagnosticへURLを出さずopaque source IDを返す。

## Setup route boundary

setup harness identity `pi`、`.pi` layout、candidate manifestを既存setup plannerへ渡し、全target mutationは `SetupTransactionCoordinator` のclosed transaction resultだけを通す。本Unitはtargetへ直接copy/remove/manifest writeを行わない。

- fresh/update/uninstall actionにはexpected-before/candidate digestとmanaged ownershipを渡す。
- retired resourceはold install manifestでmanagedかつactual digest一致の場合だけremove候補にする。
- modified managed/user file、pre-existing backup、path collisionはtransaction conflictとして保持する。
- setup payloadにsource repository root `package.json`やPi Package metadataを含めない。
- transaction `committed` receiptなしにdistribution successを返さない。

## Supply-chain controls

Pi Package extensionはload時にhost user権限でcodeを実行し、skillはモデルへtool操作を指示できる。distributionは次を強制する。

- dynamic remote code fetch、runtime self-update、post-install downloadをAmadeus extension bootstrapへ追加しない。
- generated extension/driver/skill/question annexをすべてexpected catalog digest対象にする。
- unknown extra extension、hidden file、editor backup、unexpected executable、package lifecycle hookをcandidateへ黙って含めない。
- Git pin/source review/update diff/uninstallをmandatory guide claimとしてmachine catalogへ公開する。
- local/git routeでsource revisionとresource digest集合が一致しない場合はparity failureとする。
- npm publish、registry token、release upload、signing keyを本Unitへ導入しない。署名していないartifactをsignedと表示しない。

## Secret and privacy controls

generated resource、root `pi` metadata、setup manifest、parity report、diagnosticへ次を含めない。

- provider/API/OAuth token、SSH private key、Git credential
- prompt/assistant/tool content、live session transcript
- home absolute path、username、local install root
- private installer transaction/quarantine/backup path/content

hashはsecret maskingではないため、secretをhashしてcatalog/evidenceへ載せることも禁止する。diagnosticはresource ID、normalized relative path、expected/observed digest prefix、source revision、remediationだけを返す。local absolute pathやcredential-bearing URLはopaque source IDへ変換する。

## Registry and generated drift controls

discovered harness manifestsをharness catalogの正本とし、Piだけを別の固定配列正本へ複製しない。consumer側のclosed registry（setup harness union、layout、projection/package/self-install list）が必要な場合はdiscovered catalogから生成または双方向parity検査する。

drift guardは次を検証する。

1. expected catalog ↔ setup candidateのmissing/extra/path/kind/hash/mode。
2. expected catalog ↔ root Pi Package resource declaration/actual bytes。
3. setup install result ↔ Pi Package local/git normalized installed resource集合。
4. discovered harness catalog ↔ setup/runtime/projection consumer registry。
5. same source/configの連続2回生成digest、second-run filesystem diff 0。

`dist/`やroot package projected fieldを手編集してauthored sourceへreverse importしない。Pi registry/resourceを一件削除・追加・別harnessへrenameするmutation testで、各consumer/parity guardがredになることを要求する。

## Threat matrix

| Threat | Control | Negative verification |
|---|---|---|
| target root package overwrite | setup payloadからpackage metadata除外 | setup install/updateでtarget package bytes不変 |
| resource+manifest同時削除 | verifier-bound expected catalog | both-delete mutationでmissing failure |
| path/symlink escape | normalized path + no-follow regular file | absolute/`..`/symlinkでcandidate 0 |
| generated extension改ざん | source→candidate one-way digest parity | byte mutationでpackage/setup両route fail |
| moving Git source | immutable full commit identity | branch/tag-only formal evidence 0 |
| credential-bearing URL漏洩 | credential-free canonicalizer/opaque ID | userinfo/query canaryがlog/report 0件 |
| package install script混入 | root lifecycle security profile | lifecycle field mutationでformal candidate fail |
| malicious extra extension | closed expected resource set | extra hidden/executable fileでdrift failure |
| untrusted project auto-load | Pi native trust only | install後trust前extension effect 0 |
| consumer registry omission | discovered catalog parity | Pi consumer entry削除でCI red |
| private backup配布 | explicit denylist + expected-only candidate | private-root canaryがpackage/setup inventory 0件 |

## Failure policy

| Failure | Result | Mutation/distribution policy |
|---|---|---|
| expected catalog unavailable/mismatch | distribution blocked | partial candidate 0 |
| source/path/type/digest invalid | projection failure | generated publish 0 |
| root metadata outside `pi` field diff | package projection failure | root write/commit 0 |
| unsafe lifecycle profile | formal package blocked | silent safe claim 0 |
| setup transaction conflict/failure | setup failed/recovery-required | package route successで隠さない |
| local/git parity mismatch | parity failure | formal distribution success 0 |
| registry drift | distribution drift | omitted harness success 0 |
| project untrusted | native trust pending | autoapprove/load 0 |

## Verification gate

- clean authored fixtureからsetup/package viewを連続2回生成し、normalized catalog/hash一致とsecond-run diff 0を確認する。
- targetにcanary `package.json`を置き、fresh/update/uninstallでbyte diff 0を確認する。
- resource/manifest/registry/root `pi` entryを一件ずつdelete/add/rename/hash mutateし、各guardをredにする。
- absolute/traversal/case-fold/Unicode/symlink/hidden executableをcandidate sourceへ混入し、target mutation 0を確認する。
- root lifecycle script、`private:false`、credential-bearing metadata/URL、lockfile driftをmutationし、formal package candidateを拒否する。
- local clean/dirty、git full commit/moving branch/tag-only/credential URLをproduction source parserへ通す。
- setup routeとPi Package routeのnormalized installed path/hash集合を比較し、片方のmissing/extra/hash driftを他方のhealthyで隠さない。
- fresh untrusted projectでinstall後extension effect 0、明示trust後だけresource discovery可能であることをconformance fixtureへ渡す。
- secret/home/private-backup canaryがgenerated tree、package metadata、setup manifest、parity report、diagnosticで0件であることをscanする。

検証はmanifest内の自己申告 `valid`、固定resource件数、README記載ではなく、verifier-bound catalog、actual candidate bytes、target install manifest、Pi package installed inventoryから判定する。
