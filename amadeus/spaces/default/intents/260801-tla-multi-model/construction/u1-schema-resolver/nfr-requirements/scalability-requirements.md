# Scalability Requirements — u1-schema-resolver

## 上流境界

`business-logic-model.md` の §2.3(推移閉包)/ §2.5(MirrorLifecycle の期待動作)、`business-rules.md` の BR-R5(正規化)/ BR-R8(純粋モジュール)、`requirements.md` の NFR-4(新規外部依存なし)を正本とする。

## 適用性の評価

本 Unit は単一プロセスで短時間に完走する CLI/CI 検証ツールの内部モジュールであり、同時接続・負荷分散・自動スケーリング・容量計画の概念を持たない。水平/垂直スケーリング要件、スケーリングトリガ、同時実行数目標は**適用外**とする — 根拠は実行形態(CI ジョブ内の逐次ステップ、常駐プロセスなし)であり、対象データ(登録 TLA モデル)も現行 2 モデル + aux 1 件の固定小規模集合で、第3モデル登録は requirements.md の Out of scope に明記されている。

## 成長に対する境界(適用する唯一の要件)

- 登録モデル・補助モジュールの増加に対し、リゾルバの計算量は**線形のまま**であること(推移閉包は `visited` 管理のワークリスト BFS — performance-requirements.md の計算量境界と同一規定)。モジュール数を n、総行数を m として O(n + m) を超えるアルゴリズム(全ペア比較・再帰的なソース再走査)を禁止する。
- 状態を持たない純粋関数設計(BR-R8)を維持し、モデル数増加時にキャッシュ・ワーカー等の仕組みを追加しない(現行規模で不要 — 過剰設計の禁止)。
- 宣言照合(BR-C1)の集合比較は declared / resolved ともモデル数に比例する小集合であり、集合演算の計算量は O(n log n)(ソート)を上限とする。

## Acceptance

t402 の合成モジュール列(A→B→C)ケースで推移閉包が線形に完走し、注入 stub の呼出回数がモジュール数を超えないことで合否を判定する。これ以上の負荷試験・スケール試験は実施しない(適用外の評価どおり)。
