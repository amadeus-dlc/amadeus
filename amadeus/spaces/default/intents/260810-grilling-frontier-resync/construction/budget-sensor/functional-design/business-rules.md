## BR 一覧

- **BR-U2-1(マーカー検知)**: `detectGrillingMarker` は questions ファイルの**先頭10行以内**の `<!-- amadeus-grilling:v1 mode=grilling -->`(U1/C1 正本の verbatim)を検知する。`amadeus-grilling:` タグは在るが版・属性が正本と異なる異形は「マーカーなし扱いで無音通過」ではなく **malformed-marker の warning finding**(pass 維持 — advisory 契約、ただし loud)。[FR-CONTRACT-4(i) 検知面]
- **BR-U2-2(justification 検査への切替)**: マーカー検知時、数値検査(over-budget FAIL)を justification 検査へ切り替える — 質問数が depth 上限(4/8/12)を超える場合、(a) 超過記録行 `<!-- amadeus-grilling:justification depth=<Depth> questions=<N> frontier-driven -->`(C1 正本の verbatim、`depth` は当該ファイルの depth と一致、`questions` は数値)の存在 と (b) 刈りノード列挙節の存在 を検査。(a)(b) いずれか欠落 = **FAIL finding**(`missing-justification` / `missing-deferred-list` を個別に立てる)。両方あり = PASS(reason `justified-overrun`、finding なし)。上限以内なら従来どおり within-budget。[FR-CONTRACT-4(i) 検査面、FR-PROTO-7/8 の事後検査]
- **BR-U2-2b(刈りノード列挙節の検出仕様)**: (b) の検出は U1 の **BR-U1-4** を正本とし、見出し逐語 `閾値未満として明示的に先送りした点` を対象とする(U2 で言い換えない)。走査範囲は questions ファイル**本文全域**(マーカーの先頭10行窓では合意サマリ末尾を構造的に検出できない)。述語は行頭 `#{1,6}` + 空白 + 装飾(`**`)除去後の見出しテキストの完全一致とし、**見出しレベルは非依存** — BR-U1-4 は「節」とだけ規定しレベルを定めておらず、U2 がレベルを固定すると承認済み契約へ存在しない制約を足すことになる(`cid:requirements-analysis:c2c5-structural-addition-not-execution`)。判定は節の**存在のみ**で、項目本文は見ない(FR-PROTO-7 の「空の明示は必要」— Free の空明示と刈り0件を区別してはならない)。型は `{ present: boolean }`(domain-entities)。当該節が questions ファイル内に置かれることは C3 の既承認境界(`components.md:31`)。[FR-PROTO-7 の事後検査面]
- **BR-U2-3(未知 depth の loud 化)**: depth が非 null かつ3値(Minimal/Standard/Comprehensive)外のとき、現行の `no-depth, pass:true` 無音通過を **unknown-depth の warning finding(pass 維持)** へ変更。depth null(未検出)は従来どおり no-depth。[FR-CONTRACT-4(ii)]
- **BR-U2-4(語彙非交差の vacuity guard)**: **正本トークン3種**(grilling モードマーカー・超過記録行・刈りノード列挙節見出し)が既存述語と交差しないことをテストで固定する。対象述語は (i) `[Answer]:`(ANSWER_TAG_RE) (ii) 「承認」行走査 (iii) **質問カウント述語**(`LINE_PATTERNS` / `QUESTION_HEADER_CELL`)。assert は2方向 — 正常な回答済み questions ファイルへ3トークンを注入しても (i)(ii) の answer-evidence 述語結果が不変であること、および `countQuestions` の値が不変であること。列挙節見出しは見出し形のため (iii) との交差可能性が実在する(`LINE_PATTERNS` は `^#{2,4}\s+` に続く Q コードを要求するので `閾値…` は 0 hit になる想定 — 想定でなく実測で固定する)。[ADR-2 の意味論固定]
- **BR-U2-5(VALID_DEPTH_VALUES 不変 assert)**: 契約テストで `amadeus-directive.ts` の `VALID_DEPTH_VALUES` が3値 verbatim であること、および grilling 改訂ファイル群(protocol/skill/センサー)が `"Free"` を depth の wire 値として流さないことを assert。[FR-CONTRACT-3]
- **BR-U2-6(t415 の完全改訂)**: U1 の暫定 pin を完全化 — 新契約の逐語 pin(frontier 空終了・枝刈り表見出し・遮断器規定・§8 接続段落・semi 除外文言・SKILL の Free 既定)+復活禁止 pin(旧 D6 文言・`hybrid termination`・`Continue` ラベル・`8-12+`)。**対角実測**: 改訂後 t415 × 改訂後正本 = green / 改訂前 t415 × 改訂後正本 = 赤 を実測記録。[FR-CONTRACT-6]
- **BR-U2-7(センサーテストの態+落ちる実証)**: (i) マーカー付き超過+記録・列挙あり = PASS(`justified-overrun`・finding なし) (ii) マーカー付き超過+**記録欠** = FAIL(`missing-justification`) (iii) マーカー付き超過+**列挙節欠** = FAIL(`missing-deferred-list`) (iv) 未知 depth = warning(`pass` 維持) (v) 異形マーカー = warning(`pass` 維持)。(ii)(iii) は落ちる実証 — 対応する行を注入で欠落させ、実際に error finding が出て `pass:false` へ倒れることを実測する。(iv)(v) は `pass:true` のまま finding が立つことを実測する(warning が `pass` を倒さない = `severity` 導入の実効)。テストは in-process seam(関数直接呼び出し)で駆動(bun-coverage-spawn-blindspot 回避)、実 FS を使う分は integration 層(fs-tests-integration-first)。tNNN は t530 以降を予約。FR-PROTO-8 AC の機械面は (ii)(iii) の落ちる実証で充足する(裁定 2026-08-10、BLOCKER B ユーザー裁定 — 遮断器は C1 会話時規律で C3 は消費しない(component-methods.md:18)。会話時発火の検証は FR-DOG-1)。[FR-CONTRACT-4 AC、FR-PROTO-7/8 の落ちる実証]
- **BR-U2-8(cutoff 意味論の維持と単一ゲート)**: 新検査(justification / missing-deferred-list / malformed-marker / unknown-depth)にも既存 cutoff(`QUESTION_BUDGET_CUTOFF_YYMMDD = 260809`、record 日付基準の enforced 切替)を同一適用する。**適用は分岐途中でなく単一のゲート点で行う** — finding は候補として積み、`enforced` で一括フィルタしてから verdict にする(business-logic-model.md § 判定フロー Phase 3→4)。現行実装は `enforced` を over-budget 直前でしか参照しないため(`amadeus-sensor-question-budget.ts:316`)、新 finding を分岐途中で return する形だと cutoff を迂回する経路が生まれ、cutoff 前 record の回帰不変が破れる。`!enforced` のときは `findings=[]` かつ reason を現行語彙(`no-depth` / `within-budget` / `pre-cutoff`)へ縮退させ、新語彙が enforced 側にしか現れないことを構成的に保証する。[requirements Assumptions]
- **BR-U2-9(cutoff 迂回路の不在をテストで固定)**: BR-U2-8 の単一ゲートは「どの分岐も cutoff を迂回しない」ことが要点なので、cutoff 前 record を対象に**新検査が発火しうる全入力組合せ**(異形マーカー / 未知 depth / マーカー付き超過+記録欠 / 同+列挙節欠)を通し、verdict の全フィールドが改訂前実装と同一であることを assert する。単一ケースの pre-cutoff テストでは迂回路の不在を示せない。[BR-U2-8 の検査面]
